# 🚀 Release: 0.1.0-rc.3

> **Third release candidate.** Every change since **0.1.0-rc.2**: zone
> transfers over TLS, an audit log for management changes, every zone of an
> old primary imported in one run, and the DNS plane audited against the
> RFCs it cites. Clean installs only — no upgrade path from rc.2.

## 📦 Distribution

**Debian (.deb)** and **RPM (.rpm)** packages for **amd64 and arm64**, the
**multi-arch container image** carrying the ExternalDNS adapter
(`bindizr-external-dns`), and the **Helm chart** on Docker Hub as an OCI
artifact (`oci://registry-1.docker.io/kweonminsung/bindizr-chart`), each
release attaching its **`THIRD_PARTY_LICENSES.html`**. The image now exposes
**853** for transfers over TLS.

## 📌 Installation (Debian/Ubuntu)

```bash
dpkg -i bindizr_0.1.0-rc.3-1_amd64.deb    # _arm64.deb on arm64
```

## 📌 Installation (RHEL/CentOS/Fedora)

```bash
rpm -i bindizr-0.1.0_rc.3-1.x86_64.rpm    # .aarch64.rpm on arm64
```

## 📌 Installation (Helm)

```bash
helm install bindizr oci://registry-1.docker.io/kweonminsung/bindizr-chart \
  --version 0.1.0-rc.3 \
  --set bindizr.database.existingSecret=bindizr-db-secret
```

## ⚠️ Breaking Changes

- **Configuration sections** (unknown keys are rejected): `api.tls_cert_file` /
  `api.tls_key_file` become `[api.tls] cert_file` / `key_file`,
  `dns.nsupdate_tsig_required` becomes `[dns.nsupdate] tsig_required`,
  `[dns.transfer_cache] max_records` becomes `[dns.transfer] cache_max_records`,
  and `dns.zone_history_retention_days` becomes `[history] zone_max_days`.
  Environment variables follow the TOML path (`BINDIZR_API_TLS_CERT_FILE`,
  `BINDIZR_HISTORY_ZONE_MAX_DAYS`); the chart value is
  `bindizr.dns.transfer.cacheMaxRecords`
- **`bindizr dnssec-policy …` is now `bindizr dnssec policy …`**, so every
  DNSSEC operation sits under one command; `/dnssec-policies` is unchanged
- **The daemon socket**: a root CLI drives another user's daemon only on
  `/run/bindizr`, since anyone can plant a socket under `/tmp`, and the daemon
  refuses a socket directory another user owns. The directory it creates is
  owner-only; the socket file itself is no longer chmod'ed
- **Schema replaced**: the `audit_log` table and the transfer `transport`
  column are new, and MySQL name columns are ASCII, wide enough for an escaped
  name. Rust 1.94 to build

## ✨ New Features

- **Zone transfers over TLS (XoT, RFC 9103)** — `[dns.tls]` opens a TLS 1.3
  listener (853, `dot` ALPN) that admits a transfer only under a TSIG key
  *and* a registered secondary address; `[dns.transfer] require_tls` turns
  transfers away from the plain listeners once every secondary has moved.
  Guides for BIND, Knot DNS, and NSD; `bindizr.dns.tls.existingSecret` in the
  chart; `secondary transfers`, `zone status`, `status`, `doctor`, and the
  `bindizr_xfr_total{transport}` metric say which transport served
- **Certificate reload** — `bindizr config reload` or SIGHUP re-reads the
  `[api.tls]` and `[dns.tls]` pairs, so a renewed certificate serves without
  a restart
- **Database TLS** — `[database.tls] mode` / `ca_file` name the mode for MySQL
  and PostgreSQL in one vocabulary (`disable` … `verify-full`); the chart
  mounts the CA from `bindizr.database.tls.existingSecret`
- **Audit log** — every create, update, and delete of a token, role, grant,
  TSIG key, secondary, or DNSSEC policy, and every zone deletion, leaves an
  entry naming the entity, the operation, the request path, the token, and
  what changed, never a secret. `bindizr audit list` (`--entity`, `--name`,
  `--since`/`--until` as a span ago, a date, or an RFC 3339 time, `--sort`,
  `--order`) and `GET /audit` read it under the new all-zones action
  `audit:read`; `[history] audit_max_days` prunes it beside `zone_max_days`
- **Every zone in one run** — `zone import --from-server … --zones FILE` or
  `--from-catalog NAME` (RFC 9432) imports each zone in its own transaction
  and reports every outcome; over HTTP, `POST /import`. A
  [migration guide](https://kweonminsung.github.io/bindizr/deployment/migrating/)
  walks an existing primary over. `[dns.import] timeout_secs` and
  `max_records` bound the AXFR Bindizr pulls
- **TCP limits** — `dns.tcp_idle_timeout_secs`, advertised as edns-tcp-keepalive
  (RFC 7828), and `dns.tcp_max_connections`, one cap per listener; the queries
  of one connection run concurrently
- **RFC compliance** — the DNS plane was audited against the RFCs it cites and
  the MUST-level gaps closed: RFC 2136 rcodes and the apex NS set and SOA
  surviving a delete, RFC 8945 signed refusals, one DNAME per name (RFC 6672),
  an OPT on every answer with UDP truncation and extended errors (RFC 6891,
  8914), the echoed question class and SERVFAIL for a transfer that fails
  midway (RFC 5936), SHA-256 on every DS and CDS (RFC 8624)

## 🧹 Fixes & Improvements

- **Wire values survive** — arbitrary TXT bytes, RFC 3597 record data, escaped
  labels, and serial wraparound through the API, storage, updates, and
  transfers; names embedded in DNAME, SRV, and NAPTR keep their case and sign
  correctly; wildcard UDP listeners reply from the address that was queried
- **Secondary lag** in the CLI is the wrapping serial distance, negative for a
  secondary that is ahead
- **MySQL free-text search** no longer answers 500 to a Unicode term
- **Dependencies** — rustls 0.23.46 and domain 0.12.3 pick up their advisories
  (TLS 1.3 handshake messages across encryption levels; RUSTSEC-2026-0310)
- **Large requests** — ExternalDNS change sets, zone-file import, and rollback
  match records by identity instead of comparing every pair, and the transfer
  cache evicts in one pass
- **SQLite** refuses a row id past the 32-bit range instead of truncating it
- The test suite names every case for the behaviour it verifies
