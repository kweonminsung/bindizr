# 🚀 Release: 0.2.0-rc.1

> **First release candidate of 0.2.0.** Every change since **0.1.0**: three
> logs — audit, access and transfer — read one way under `/logs`, and the web
> UI rearranged around them. Clean installs only — no upgrade path from 0.1.0.

## 📦 Distribution

**Debian (.deb)**, **RPM (.rpm)**, and **Alpine (.apk)** packages for
**amd64 and arm64**, a **multi-arch container image** carrying the ExternalDNS
adapter, and the **Helm chart** at
`oci://registry-1.docker.io/kweonminsung/bindizr-chart`.
The GitHub release also includes **`THIRD_PARTY_LICENSES.html`**.

## 📌 Installation (Debian/Ubuntu)

```bash
dpkg -i bindizr_0.2.0-rc.1-1_amd64.deb    # _arm64.deb on arm64
```

## 📌 Installation (RHEL/CentOS/Fedora)

```bash
rpm -i bindizr-0.2.0_rc.1-1.x86_64.rpm    # .aarch64.rpm on arm64
```

## 📌 Installation (Alpine)

```bash
apk add --allow-untrusted bindizr-0.2.0_rc1-r1.x86_64.apk    # .aarch64.apk on arm64
```

## 📌 Installation (Helm)

With a database connection secret already created:

```bash
helm install bindizr oci://registry-1.docker.io/kweonminsung/bindizr-chart \
  --version 0.2.0-rc.1 \
  --set bindizr.database.existingSecret=bindizr-db-secret
```

See the [deployment guides](https://kweonminsung.github.io/bindizr/deployment/kubernetes/)
for database secrets, secondary servers, and TLS configuration.

## ⚠️ Breaking Changes

- **Every log under `/logs`**: `GET /audit` is now `GET /logs/audit` and
  `bindizr audit list` is `bindizr log audit`. `GET /secondaries/{name}/transfers`
  and `bindizr secondary transfers` are gone; `GET /logs/transfer?secondary_name=`
  and `bindizr log transfer --secondary` take their place
- **`audit:read` is now `log:read`** and reads all three logs;
  `secondary:read` no longer reads transfer history
- **Configuration**: `[history] zone_max_days` and `audit_max_days` become
  `[history] max_days` and `[audit_log] max_days`, beside the new
  `[access_log]` and `[transfer_log]`. Environment variables and chart values
  follow the TOML path (`BINDIZR_AUDIT_LOG_MAX_DAYS`, `bindizr.auditLog.maxDays`)
- **Sorting**: a tie is broken by the row id in the sort's own direction, so
  zone and record listings sorted descending return tied rows in a new order
- **API schema**: `TransferResponse` is renamed `TransferLogResponse`
- **Schema replaced**: the `transfers` table is now the append-only
  `transfer_log`, and `access_log` is new

## ✨ New Features

- **Access log** — every management API request and nsupdate Bindizr answered,
  denied, or failed: the client address, the method and path or the zone, the
  status or RCODE, the token or TSIG key that verified, and the error. Rows are
  written off the request path; a full queue drops and counts them in
  `bindizr_access_log_dropped_total`. `bindizr log access`, `GET /logs/access`
- **Transfer log** — every transfer answered, refused, or failed, kept as
  history by client address and zone, refusals to addresses no secondary has
  included. `bindizr log transfer`, `GET /logs/transfer`
- **One way to read the logs** — filters, a time window, paging, and
  `--sort`/`--order` (`sort`/`order` over HTTP) on all three
- **What a log keeps** — `access_log.save = all | denied | none` and
  `transfer_log.save = all | unserved | none`; `max_days` bounds each
- **Web UI** (bindizr-ui 0.2.0-rc.1) — Logs and DNSSEC as sidebar groups, the
  access and transfer log pages, and every listing laid out alike, its filters
  and sort on one line

## 🧹 Fixes & Improvements

- **Sort parameters** — `sort` and `order` ignore case and surrounding space,
  an empty value takes the default, and a rejected value lists the accepted ones
- **Configuration reference** — every setting with a fixed set of values,
  booleans included, lists them as `a | b | c` in the commented config, the
  chart values, and the environment table
- **Dependencies** — clap 4.6.8, nix 0.32, rand 0.10.4, axum-server 0.9.1,
  toml 1.2.1, openssl 0.10.82, and the Rust 1.100 build image
